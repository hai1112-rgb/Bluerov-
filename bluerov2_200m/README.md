# BlueROV2 200 m Simulation Workspace

ROS 2 Jazzy workspace for a BlueROV2-style underwater vehicle simulation with a nominal operating region extending to approximately 200 m depth. The repository combines vehicle description, Gazebo simulation, RViz visualization, simulated sensing, localization, waypoint control, manual teleoperation, and six-thruster allocation.

This project is intended for simulation, research, and educational development. It is not a replacement for BlueOS, ArduSub, or real-vehicle safety systems, and the 200 m configuration refers to the simulated environment rather than hardware pressure certification.

## Features

- BlueROV2-style URDF and Gazebo SDF/Xacro model
- Deep-water Gazebo environment with a 200 m water column
- Front FPV camera bridge for ROS 2
- Forward and downward sonar simulation
- Simulated IMU, DVL, depth, and magnetometer data
- Localizer publishing odometry, path, and TF
- Waypoint autopilot with click-to-go and depth setpoint support
- Six-thruster virtual allocation for 6-DOF wrench commands
- Terminal and Tk-based manual teleoperation
- Configurable current, storm, and thruster-fault disturbances
- RViz configurations for navigation and vehicle inspection
- MATLAB/Simulink reference assets retained under `src/bluerov2_control/MatlabSrc/`

## Repository Structure

```text
.
|-- src/
|   |-- bluerov2_description/   # Robot model, frames, meshes, URDF/Xacro, Gazebo model
|   |-- bluerov2_control/       # Dynamics, sensors, localization, control, teleop, thruster allocation
|   `-- bluerov2_gazebo/        # Gazebo world, integrated launch files, RViz configuration
|-- docs/                       # Physics notes and terminal workflow guide
|-- doc/                        # Additional reference material
|-- CHECK_REPORT_200M.md        # Validation and runtime notes
|-- LICENSE
`-- README.md
```

`build/`, `install/`, and `log/` are generated by colcon and are intentionally excluded from version control.

## Requirements

Recommended environment:

- Ubuntu 24.04
- ROS 2 Jazzy
- Gazebo with ROS-Gz integration
- Python 3

Install the main dependencies:

```bash
sudo apt update
sudo apt install \
  ros-jazzy-desktop \
  ros-jazzy-ros-gz \
  ros-jazzy-xacro \
  python3-colcon-common-extensions \
  python3-numpy \
  python3-tk \
  python3-yaml
```

## Build

From the workspace root:

```bash
source /opt/ros/jazzy/setup.bash
colcon build --packages-select bluerov2_description bluerov2_control bluerov2_gazebo
source install/setup.bash
```

After modifying files under `src/`, rebuild the affected package(s) and source the workspace again.

## Quick Start

### Headless Gazebo simulation

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch bluerov2_gazebo start_enhanced_world.launch.py
```

### Gazebo with RViz

```bash
ros2 launch bluerov2_gazebo start_enhanced_world.launch.py open_rviz:=true
```

### Gazebo GUI with RViz

```bash
ros2 launch bluerov2_gazebo start_enhanced_world.launch.py gz_gui:=true open_rviz:=true
```

### Autonomous demo

```bash
ros2 launch bluerov2_gazebo start_autonomous_demo.launch.py open_rviz:=true
```

### RViz navigation demo

```bash
ros2 launch bluerov2_gazebo start_rviz_navigation_demo.launch.py
```

## Main ROS 2 Topics

| Topic | Type | Purpose |
| --- | --- | --- |
| `/bluerov2/pose_gt` | `nav_msgs/Odometry` | Ground-truth vehicle pose |
| `/bluerov2/localized_pose` | `nav_msgs/Odometry` | Localized vehicle pose |
| `/tf`, `/tf_static` | `tf2_msgs/TFMessage` | Vehicle, sensor, and thruster transforms |
| `/bluerov2/robot_description` | `std_msgs/String` | Robot description used by RViz |
| `/bluerov2/sonar/forward` | `sensor_msgs/LaserScan` | Forward sonar data |
| `/bluerov2/sonar/downward` | `sensor_msgs/LaserScan` | Downward sonar data |
| `/bluerov2/sonar/spherical_cloud` | `sensor_msgs/PointCloud2` | Sonar point cloud |
| `/bluerov2/camera/front/image` | `sensor_msgs/Image` | Front FPV camera image |
| `/bluerov2/camera/front/camera_info` | `sensor_msgs/CameraInfo` | Front camera calibration metadata |
| `/bluerov2/thrusters/thruster_N/input` | `std_msgs/Float64` | Gazebo thruster command input |

## FPV Camera

The Gazebo model includes a forward-facing camera mounted at the vehicle nose. Example topic checks:

```bash
ros2 topic echo /bluerov2/camera/front/image --once
ros2 topic echo /bluerov2/camera/front/camera_info --once
```

The RViz configuration at `src/bluerov2_gazebo/rviz/autonomous.rviz` includes camera and vehicle-follow views.

## Validation

Compile-check the Python scripts and launch files:

```bash
python3 -m compileall -q \
  src/bluerov2_control/scripts \
  src/bluerov2_control/launch \
  src/bluerov2_description/launch \
  src/bluerov2_gazebo/launch
```

Build and run package tests:

```bash
source /opt/ros/jazzy/setup.bash
colcon build --packages-select bluerov2_description bluerov2_control bluerov2_gazebo
colcon test --packages-select bluerov2_description bluerov2_control bluerov2_gazebo
colcon test-result --verbose
```

Validate the Gazebo world:

```bash
gz sdf -k src/bluerov2_gazebo/worlds/bluerov2_demo.sdf
```

Validate the generated Gazebo model:

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
xacro src/bluerov2_description/models/bluerov2_gz.sdf.xacro namespace:=bluerov2 >/tmp/bluerov2_gz.sdf
gz sdf -k /tmp/bluerov2_gz.sdf
```

Validate the generated URDF:

```bash
xacro src/bluerov2_description/robots/bluerov2_default.xacro namespace:=bluerov2 >/tmp/bluerov2_default.urdf
check_urdf /tmp/bluerov2_default.urdf
```

See [`CHECK_REPORT_200M.md`](CHECK_REPORT_200M.md) for additional validation and runtime notes.

## Graphics Troubleshooting

The Gazebo GUI defaults to the `ogre` renderer for broader compatibility with NVIDIA and hybrid-GPU systems.

To try OGRE2 explicitly:

```bash
ros2 launch bluerov2_gazebo start_enhanced_world.launch.py \
  gz_gui:=true gz_render_engine:=ogre2
```

If RViz encounters OpenGL/GLX issues, try Mesa rendering:

```bash
ros2 launch bluerov2_gazebo start_enhanced_world.launch.py \
  open_rviz:=true glx_vendor:=mesa
```

The simulation can also be run headless when a graphical environment is unavailable.
